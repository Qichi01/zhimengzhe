# 已解决：关键场景配图触发与刷新重复生成

> 记录日期：2026-08-05
> 解决日期：2026-08-07
> 状态：已解决
> 优先级：P1
> 影响版本：V2.2 AI 配图 / V3.0 基线

## 历史现象

- 开启“AI 场景配图”后，故事正文可以正常生成，但关键场景仍没有出现实际插图。
- 原先泄漏到正文中的内部标记（例如“配图建议：关键”）已经被过滤，当前不会再向用户展示。
- 图片出现时机不稳定；刷新阅读页后可能再次生成正文和配图，增加等待时间和请求次数。

## 根因

- 首场景配图判断、图片 API、客户端压缩和 IndexedDB 写回链路本身均可正常工作。
- 阅读页在 URL 没有 `save` 或 `review` 参数时，一律把当前访问当作“新的开始”，没有读取已有场景。
- 因此刷新正在游玩的页面会以空场景挂载阅读器，再次调用聊天与配图接口；重复请求让用户误以为配图没有触发或长时间无结果。

## 修复

- “新的开始”仍由游戏菜单在跳转前显式清空旧进度。
- 阅读页直接访问或刷新时从 IndexedDB 恢复当前场景；已有场景时不再自动调用聊天或配图接口。
- 插图生成成功后检查 IndexedDB 写回结果；写回失败按配图失败处理，不展示无法持久化的临时图片。

## 当前降级行为

- 不显示“配图建议”等内部控制文本。
- 没有图片时不保留空白占位，不弹出阻断提示，正文和选项继续正常工作。
- 不自动高频重试，避免产生额外图片请求和成本。

## 验证结果

- 开启配图后的新游戏首场景同时触发 `/api/chat` 与 `/api/illustration`，两者均返回 200，插图显示在正文上方并写入 IndexedDB。
- 修复后刷新阅读页，已有正文、插图和选项直接恢复，没有新增聊天或配图 POST 请求。
- 浏览器模拟配图接口返回 502 时，正文与四个选项仍正常显示，不保留加载占位，不泄漏内部提示词。
- 1440×900 桌面端与 390×844 手机端通过；手机端无整页横向溢出。
