# 织梦者 V3.0 阶段 0 工程设计

> 日期：2026-08-05
> 状态：协议与本地运行时底座已实现

## 1. 本阶段目标

在不改变 V2.1 旧游戏阅读流程的前提下，先建立 V3 共用的叙事协议和本地运行时，使校园乙游、无限流及后续题材包能消费同一条剧情时间线。

数据流固定为：

`模型原始输出 → 白名单校验 → 题材事件过滤 → 幂等状态物化 → IndexedDB 原子提交 → UI 读取领域状态`

界面组件不得直接读取或执行模型生成的 HTML、样式、组件名称和未经校验的事件 payload。

## 2. 已实现模块

### 2.1 统一类型

- `NarrativeFrame`：正文、选项、关键度、事件、状态补丁与配图提示。
- `NarrativeEvent`：消息、论坛、日历、任务、道具、商店和关系更新七类白名单事件。
- `WorldDefinition`：不可变世界档案与 `VisualBible`。
- `WorldState`：可重放的消息、帖子、任务、道具、关系、未读数和事件游标。
- `GenrePackDefinition`：题材模块、允许事件与视觉 token。

### 2.2 事件校验

- 未知事件类型直接拒绝。
- 每种事件单独校验必填字段、长度、数量和枚举值。
- 同一帧重复事件 ID 拒绝写入。
- 题材包未授权的合法事件同样拒绝，例如校园乙游不能收到系统商店事件。
- 单个事件失败不丢弃正文；失败事件进入本地待修复队列。

### 2.3 幂等运行时

- `appliedEventIds` 防止请求重试或读档重放造成重复消息、重复道具和重复未读数。
- 道具发放采用事件级累加，同一事件只能生效一次。
- 状态补丁和事件在同一次物化过程中提交。
- 校园消息路由到私聊，无限流消息路由到队伍频道。

### 2.4 本地存储

IndexedDB 当前版本升级到 3，保留原有对象仓库并增加：

- `world_definitions`
- `world_states`
- `narrative_frames`
- `narrative_events`
- `narrative_event_failures`
- `module_states`
- `assets`
- `story_sources`
- `world_drafts`

叙事帧、合法事件和物化状态在同一 IndexedDB 事务中写入。相同 `frame.id` 再次提交时直接跳过。清空游戏或删除游戏时同步清理所有 V3 数据。

## 3. 首发题材包

### 校园乙游

- 正文、私聊、动态、校园论坛、日历、人物关系、档案。
- 允许消息、论坛、日历和关系事件。

### 无限流

- 正文、系统面板、队伍频道、背包、商店、玩家论坛、人物关系、档案。
- 允许消息、论坛、任务、道具、商店和关系事件。

## 4. 兼容策略

- V2.1 现有类型、场景表和阅读器保持不变。
- IndexedDB 升级只新增对象仓库，不删除、不重建旧仓库。
- V3 新游戏后续通过显式模式标记进入新运行时；旧游戏不会自动转换。
- 任何 V3 事件失败都不能影响 V2.1 正文和存档。

## 5. 下一步

1. 为新游戏增加 V2/V3 模式标记与世界档案确认流程。
2. 将一条模拟 `NarrativeFrame` 接入校园手机和无限流系统面板原型。
3. 增加 TXT/Markdown 导入与本地分段。
4. 将主叙事提示词升级为正文流 + 结构化事件尾包。
5. 增加读档事件重放和模块未读状态验收。
